# 요구사항 정의서 — 자격증 장기 플래너

## 1. 도메인과 선택 조건 충족 근거 (명세 2.1)

**도메인**: 분야나 목표 자격을 말하면, 공식 시험 일정을 확인해 사람들이 많이 따는 자격 흐름대로 "무엇을 · 어떤 순서로 · 늦어도 언제부터 공부할지" 장기 계획을 짠다.

| 조건 | 근거 |
|---|---|
| ① 서로 다른 정보를 주는 외부 API 3종 이상 | 큐넷 종목 목록(후보) · 큐넷 시험일정 · 응시료 · 합격률(상세) · 카카오 책 검색(보조). 보충으로 공공데이터포털 자동변환 API 12종. 1일차 14:34 실제 호출 3/3 확인 (`scripts/check_apis.py`) |
| ② Tool 결과를 제약과 비교해야 답할 수 있는 요청 3개 이상 + 의미 있는 재계획 | 아래 2장. 접수 마감 · 준비 기간 · 기한 · 같은 날 시험 · 예산을 회차 날짜와 비교해야 하고, 불가하면 다음 후보 · 다음 회차 · 기한 완화로 재계획한다 |
| ③ 저장 · 관리할 결과물 | 자격별 응시 계획(자격, 시험일, 시각, 실기일, 접수 마감, 공부 시작일, 추정 여부, 출처). 같은 날짜 시간 겹침은 저장하고 알린다 |
| 위험 도메인 여부 | 건강 · 금융 조언이 아니므로 면책 문구는 두지 않는다. 다만 "공부 기간은 서비스 기준값", "추정 일정은 공고 후 재확인" 을 항상 표시한다 |

## 2. 대표 요청과 "Tool 없이 LLM 만으로 답하면 틀리는 것" (명세 2.7)

| 요청 | 기준 · 선호 · 제약 조건 | LLM 만으로 답하면 틀리는 것 |
|---|---|---|
| "전기 쪽으로 취업하고 싶어. 자격증 계획 짜줘" | 선호: 분야 전기 | 2027년 회차 날짜 · 접수 기간은 학습 이후 정보라 지어낸다. 어느 자격을 많이 따는지(합격자 수)도 모른다 |
| "전기기사 3월까지 따고 싶어" | 기준: 오늘, 제약: 기한 3월 말 | 준비 기간과 실제 회차를 비교하지 않고 "가능하다" 고 답한다 → 실제로는 불가, 재계획 필요 |
| "조리사로 일하고 싶어" → "양식은 빼고 다시" | 선호: 분야 조리, 후속: 제외 | 상시시험 회차 · 실기 일정을 지어내고, 후속 요청에서 앞 조건을 잃는다 |
| "9급 공무원이랑 한국사 같이 준비할래" | 선호: 공무원 + 한국사 | 서로 다른 기관의 일정을 맞춰 보지 않아 시험일이 겹치거나 순서가 틀린다 |
| "간호사 국가시험 언제야?" | 사실 조회 | 다음 시험 접수가 이미 끝났다는 사실을 모르고 지난 날짜를 말한다 |
| "자격증 따고 싶어" | 조건 부족 | (Tool 을 부르기 전에 되묻는다) |

### Tool 출력 구조 대조 — 실제 응답에서 발견해 반영한 것

| 발견 | 반영 |
|---|---|
| 사회복지사 1급 2027 회차는 시험일이 비어서 온다 | `NO_EXAM_DATE` 도메인 실패 코드, 채우지 않고 제외 |
| 2027년 일정이 아직 공고되지 않았다 (`implYy=2027` 을 줘도 2026 반환) | 2026 같은 회차 +1년을 "추정" 으로 표시 (F3002 추정 요구와 같은 구조) |
| 상시시험(기능사)은 회차가 연 40회 이상, 올해 남은 회차만 온다 | 공고 회차 뒤로 다음 해 추정을 잇고, 달마다 첫 회차만 남김 |
| 데이터진흥원 시험명이 해마다 바뀌고 필기 · 실기가 다른 행 | `name_map` 으로 묶고 단계(stage)를 회차에 붙임 |
| 국시원 접수기간이 "A ~ B" 한 칸 | 범위 칸 처리(`ranges`) |
| 카카오 책 검색 정확도순은 옛 판이 위 | 최신순 + 제목 일치 필터 |
| 알라딘 OpenAPI 는 `www` 도메인 서비스 종료, YES24 는 공개 API 없음 | 카카오(·네이버) 책 검색으로 결정 |
